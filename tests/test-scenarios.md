# Тестовые сценарии

## Статическая структура

- JSON является массивом.
- ID уникальны.
- Все wire targets существуют.
- Palette dependencies закреплены точными версиями.
- В Git отсутствуют секретные значения.

## Нормализация каждого газа

| Raw | Ожидаемое давление | Ожидаемое состояние |
|---:|---:|---|
| 0 | 0.0 bar | Тестовая тревога |
| 35 | 3.5 bar | Граница test warn |
| 40 | 4.0 bar | Граница test ok |
| 60 | 6.0 bar | Граница test ok |
| 65 | 6.5 bar | Граница test warn |
| 66 | 6.6 bar | Тестовая тревога |
| 32767 | отсутствует | `НЕТ ДАННЫХ` |
| absent/NaN | отсутствует | `НЕТ ДАННЫХ` |

Пороговые ожидания являются стендовыми до утверждения владельцем требований.

## Потеря данных

1. Подать корректное значение.
2. Прекратить сообщения Modbus.
3. Убедиться, что после согласованного timeout статус становится `НЕТ ДАННЫХ`.
4. Убедиться, что старое число не выглядит актуальным.
5. Восстановить данные и проверить recovery.

## InfluxDB

- корректное значение записывается с правильным gas tag;
- invalid sample не записывается как давление;
- данные остаются после restart;
- ошибка InfluxDB не останавливает monitoring;
- read и write используют один bucket.

## Контейнеры

- cold start;
- restart Node-RED;
- restart InfluxDB;
- полный `compose down/up`;
- сохранение volumes;
- backup и restore в отдельный project.
