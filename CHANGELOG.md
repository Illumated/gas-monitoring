# Changelog

Все существенные изменения проекта документируются в этом файле.

## [Unreleased]

### Added

- Зафиксирован исходный экспорт `flows/flows.json` и его происхождение.
- Добавлена воспроизводимая Docker-архитектура Node-RED и InfluxDB.
- Добавлены статическая проверка и аудит структуры flow.
- Реализован продуктовый Modbus TCP flow для профилей 3/4/5: O₂, AIR, VAC, N₂O и CO₂ с Input Registers, валидацией, масштабированием и stale-контролем.
- Реализованы полноэкранный HMI и интерактивная история на FlowFuse Dashboard.
- Запись и чтение InfluxDB переведены на v2 HTTP API без credentials в flow.
- Добавлен отдельный Modbus TCP simulator и FAT-профиль без обхода Modbus nodes.
- Добавлены конфигурируемые пороги, гистерезис и динамическая шкала HMI.
- Подготовлены уведомления MAX по переходам состояния без хранения токена в Git.
- Добавлена обязательная процедура настройки WB-MAI6: пять входов 4–20 мА/`0…100` и опциональный сухой контакт IN6P.
- Добавлены Debian 13 deployment, systemd, kiosk, production override и Linux backup/restore.
- Удалены legacy `node-red-dashboard` и `node-red-contrib-influxdb`; repository audit не содержит известных уязвимостей.
- Подтверждена совместимость с Node-RED 5.0.1 и Node.js 24 на закреплённом image digest.
- Исправлена высота FlowFuse `ui-template`: monitoring и history используют viewport без внутренней прокрутки на 1280×720, 1366×768 и 1920×1080.
- Исправлены скрытые внутренней симуляцией дефекты: runtime-подстановка Modbus settings и единица `startDelayTime` в секундах.
- Добавлена понятная команда `scripts/fat.ps1`; simulator возвращает применённый сценарий и регистры.
- Добавлена кроссплатформенная автоматизация WB-MAI6 и полная карта 6 каналов / 12 однополярных входов.
- Опрос пяти газов и обратной связи объединён в последовательный цикл `2 s` с задержкой очереди `300 ms`; stale timeout установлен `6 s`.
- Добавлен справочник всех переменных `.env`, включая единицы измерения и ограничения таймингов.
- Устранены ложные переходы `НОРМА` ↔ `НЕТ ДАННЫХ`: stale определяется централизованно по возрасту последнего измерения, без таймера на каждый Modbus-ответ.
- История переведена на динамические пороги и шкалу; разрывы данных больше не соединяются линией.
- Добавлены постоянный журнал переходов и аудит изменения порогов.
- Добавлена сервисная диагностика с защищённым persistent-управлением порогами.
- Retention InfluxDB закреплён на 365 суток и принудительно проверяется при запуске.
- Добавлены MAX mock, retry, напоминания и отображение состояния доставки.
- Добавлен автоматизированный software fault FAT и Debian 13 package validator.
- Добавлена обязательная идентификация установки в HMI, InfluxDB, журнале и MAX.
- MAX-сообщения разделены на аварию, предупреждение, потерю данных, восстановление и напоминание; добавлены расположение, время и длительность нарушения.
- Добавлены автоматические контракты всех порогов, гистерезиса, шаблонов MAX и persistent-настроек.
- Добавлены расчёт годовой ёмкости, value-oriented secret scan и единый release-check с Debian 13 syntax-check.
- ID установки читается без преобразований из Debian hostname строгого формата `RINIR-XXXXXX`; его формирование оставлено общему `firstboot.sh`.
- Название больницы и расположение перенесены в persistent-настройки сервисной консоли и используются в HMI, истории, журнале и MAX.
- Экран мониторинга развёрнут без стандартной рамки FlowFuse, заголовок сокращён до «Контроль давления», часы оформлены отдельной статусной плашкой.
- Значения давления и плашки состояния увеличены; цвет значения синхронизирован с состоянием канала: зелёный, жёлтый или красный.
- Обозначения каналов увеличены; канал AIR отображается как «Сжатый воздух», конкретное назначение подтверждается проектом объекта.
- Добавлены адаптивные раскладки 3/4/5 каналов для 1366×768 и 1920×1080.
- Добавлена опциональная схема WB‑MR3LV/I: удерживаемый K1, обратная связь IN6P, режимы контроля/автоматики, журнал и MAX.
- Для аварийных карточек добавлена мягкая красная пульсация контура с поддержкой системного режима уменьшения анимации.
- Добавлен единый операторский скрипт `scripts/simulation.ps1` для запуска, переключения сценариев, просмотра состояния и остановки эмуляции.
- Добавлен автономный заводской контур Debian 13 amd64: destructive preseed, offline package/image bundle, первый запуск, `RINIR-XXXXXX`, два LAN, Salt minion и приёмочный отчёт.
- Минимальный UI целевого устройства ограничен LightDM/Openbox/Chromium kiosk; удалённый dashboard опубликован отдельно через self-signed HTTPS и Basic Authentication.
- Добавлены nftables-правила: management LAN принимает только `443/tcp`, Modbus LAN не получает gateway/DNS и не публикует Node-RED или InfluxDB.
- Исправлено стирание несохранённых полей объекта фоновым обновлением сервисной страницы.
- Добавлен реестр исполнителей `персональный код → ФИО`: коды хэшируются, исполнитель подставляется сервером, регистрация и удаление доступны только администратору.
- Добавлен persistent auth-service для удалённого HTTPS-доступа; пользователи управляются из сервисного UI, пароли сохраняются как `scrypt`-хэши.
- Исправлен запуск Windows factory builder из чистого Git clone без каталога `node_modules`; для GitHub ZIP добавлена ранняя понятная диагностика.
- Исправлено создание рабочего каталога `/work` перед нормализацией заводской конфигурации в Windows factory builder.
- Добавлен zero-touch Debian Installer: автоматический UEFI/Legacy BIOS boot через 10 секунд, critical preseed без вопросов и защита готовой RINIR-системы от повторной очистки.
