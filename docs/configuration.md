# Переменные конфигурации

Рабочие значения задаются в локальном файле `.env`, созданном из `.env.example`. Файл `.env` не добавляется в Git. После изменения переменных контейнер `node-red` необходимо пересоздать:

```bash
docker compose --env-file .env -f docker/compose.yaml up -d --force-recreate node-red
```

## Общие параметры

| Переменная | Единица | Значение по умолчанию | Назначение |
|---|---|---:|---|
| `COMPOSE_PROJECT_NAME` | — | `gas-monitoring` | Имя Docker Compose project и префикс ресурсов. |
| `TZ` | IANA timezone | `Europe/Moscow` | Часовой пояс интерфейса и контейнеров. |
| `NODE_RED_PORT` | TCP port | `1880` | Локальный порт Dashboard и редактора Node-RED. |
| `NODE_RED_CREDENTIAL_SECRET` | строка | обязательно заменить | Ключ шифрования Node-RED credentials. После ввода в эксплуатацию менять его без процедуры миграции нельзя. |
| `NODE_RED_ADMIN_USER` | строка | `admin` | Имя пользователя редактора Node-RED. |
| `NODE_RED_ADMIN_PASSWORD_HASH` | bcrypt hash | пусто | Хеш пароля редактора. Пароль в открытом виде не используется. |
| `AUTH_SERVICE_TOKEN` | секрет | обязательно заменить | Внутренний токен между Node-RED и сервисом управления удалёнными пользователями. |
| `AUTH_SERVICE_PORT` | TCP port | `18082` | Loopback-only порт auth-service для nginx. |
| `REMOTE_INITIAL_USER` | строка | `operator` | Первый удалённый пользователь, создаваемый только при пустом `auth-data`. |
| `REMOTE_INITIAL_PASSWORD` | секрет | обязательно заменить | Начальный пароль; после создания пользователя в `auth-data` не используется для проверки входа. |

## Идентификация установки

В production идентификатор установки не задаётся в `.env`. Контейнер читает Debian hostname из `/etc/hostname` без нормализации или изменения. Допустимый формат — строго `RINIR-XXXXXX`, где `XXXXXX` — шесть заглавных латинских букв или цифр. Формирование такого hostname будет выполняться общим `firstboot.sh`; этот проект только проверяет и использует готовое имя.

Windows используется только для разработки и FAT. Профиль FAT передаёт явный тестовый ID `RINIR-TEST01` и не читает Windows hostname.

Название больницы и расположение вводятся после запуска через `/dashboard/engineering`. Поля сохраняются в persistent Node-RED context, попадают на HMI, в историю, журнал событий и MAX. ID установки на сервисной странице доступен только для чтения. Серийные номера WB-MAI6, USR-DR134 и датчиков фиксируются отдельно в аппаратном протоколе.

## Modbus и контроль актуальности

| Переменная | Единица | Значение по умолчанию | Назначение и ограничения |
|---|---|---:|---|
| `MODBUS_HOST` | hostname или IPv4 | `192.168.50.10` | Адрес шлюза USR-DR134. |
| `MODBUS_PORT` | TCP port | `502` | Порт Modbus TCP шлюза. Допустимо `1…65535`. |
| `MODBUS_UNIT_ID` | Modbus address | `65` | Адрес WB-MAI6 на стороне Modbus RTU. Допустимо `1…247`. |
| `MODBUS_POLL_INTERVAL_MS` | ms | `1000` | Период полного цикла O₂ → AIR → N₂O. Каждый канал опрашивается один раз за цикл. Допустимо от `500`; профиль менее `1000` применяется только после стендового испытания WB-MAI6. |
| `MODBUS_COMMAND_DELAY_MS` | ms | `300` | Минимальная задержка очереди между последовательными Modbus-командами. Для трёх каналов должно выполняться `MODBUS_COMMAND_DELAY_MS × 3 < MODBUS_POLL_INTERVAL_MS`. |
| `GAS_STALE_TIMEOUT_MS` | ms | `4000` | Максимальный возраст последнего корректного значения. После этого канал получает статус `НЕТ ДАННЫХ`. Значение должно быть не меньше трёх периодов опроса. |

При стандартном профиле три запроса помещаются в один цикл без параллельной передачи:

```text
цикл 1000 ms
├── O₂
├── задержка очереди 300 ms
├── AIR
├── задержка очереди 300 ms
└── N₂O
```

Уменьшение только `MODBUS_POLL_INTERVAL_MS` без согласованного изменения задержки запрещено: это может создать постоянно растущую очередь. Увеличение `GAS_STALE_TIMEOUT_MS` увеличивает время, в течение которого последнее значение считается актуальным.

## Отображение и пороги

| Переменная | Единица | По умолчанию | Назначение |
|---|---|---:|---|
| `GAS_HYSTERESIS_BAR` | bar | `0.1` | Гистерезис возврата из предупреждения или аварии, защищающий от дребезга состояния на границе. |
| `GAS_DISPLAY_MAX_BAR` | bar | `8` | Верхняя граница шкалы Dashboard. Должна быть выше всех порогов. |
| `OXYGEN_WARN_LOW_BAR` | bar | `3.5` | Нижняя внешняя граница предупреждения O₂. |
| `OXYGEN_OK_LOW_BAR` | bar | `4` | Нижняя граница нормы O₂. |
| `OXYGEN_OK_HIGH_BAR` | bar | `6` | Верхняя граница нормы O₂. |
| `OXYGEN_WARN_HIGH_BAR` | bar | `6.5` | Верхняя внешняя граница предупреждения O₂. |
| `AIR_WARN_LOW_BAR` | bar | `3.5` | Нижняя внешняя граница предупреждения AIR. |
| `AIR_OK_LOW_BAR` | bar | `4` | Нижняя граница нормы AIR. |
| `AIR_OK_HIGH_BAR` | bar | `6` | Верхняя граница нормы AIR. |
| `AIR_WARN_HIGH_BAR` | bar | `6.5` | Верхняя внешняя граница предупреждения AIR. |
| `N2O_WARN_LOW_BAR` | bar | `3.5` | Нижняя внешняя граница предупреждения N₂O. |
| `N2O_OK_LOW_BAR` | bar | `4` | Нижняя граница нормы N₂O. |
| `N2O_OK_HIGH_BAR` | bar | `6` | Верхняя граница нормы N₂O. |
| `N2O_WARN_HIGH_BAR` | bar | `6.5` | Верхняя внешняя граница предупреждения N₂O. |

Для каждого газа порядок должен быть таким:

```text
WARN_LOW ≤ OK_LOW < OK_HIGH ≤ WARN_HIGH < GAS_DISPLAY_MAX_BAR
```

Значения в репозитории являются стендовыми. Производственные пороги вводятся только по утверждённому документу пусконаладки.

## MAX

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `MAX_NOTIFICATIONS_ENABLED` | `false` | Включает отправку уведомлений о переходах состояния. |
| `MAX_API_URL` | `https://platform-api2.max.ru` | Базовый URL API. |
| `MAX_BOT_TOKEN` | пусто | Токен бота. Секрет, не хранится в Git. |
| `MAX_CHAT_ID` | пусто | Идентификатор получателя уведомлений. |
| `MAX_REMINDER_INTERVAL_MINUTES` | min | `30` | Интервал напоминаний, пока канал остаётся не в `НОРМА`. |
| `MAX_RETRY_COUNT` | попытки после первой | `2` | Повторные отправки при HTTP-ошибке; допустимо `0…5`. |

## Сервисная консоль

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `ADMIN_ACCESS_CODE` | пусто | Код администрирования исполнителей, удалённых пользователей и системных настроек. |
| `SERVICE_ACCESS_CODE` | пусто | Устаревший fallback для `ADMIN_ACCESS_CODE`; для новых установок остаётся пустым. |
| `SERVICE_UNLOCK_MINUTES` | `15` | Продолжительность сервисной сессии, максимум 60 минут. |

Администраторский код хранится только в `.env` с ограниченными правами. Персональные коды создаются через UI, сохраняются как HMAC-SHA-256 и привязывают каждое изменение к зарегистрированному ФИО. Имя исполнителя с клиента не принимается. Название больницы, расположение, пороги и реестр исполнителей хранятся в persistent Node-RED context.

## Хранение InfluxDB

| Переменная | Единица | По умолчанию | Назначение |
|---|---|---:|---|
| `INFLUXDB_RETENTION` | `h`, `d` или `w` | `8760h` | Срок хранения измерений и событий: 365 суток. |

Одноразовый сервис `influx-retention` проверяет и при необходимости обновляет retention существующего bucket перед запуском Node-RED. Это распространяет правило не только на новые volumes.
