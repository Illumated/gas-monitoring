# 13. Сервисная консоль

Локальный адрес: `http://127.0.0.1:1880/dashboard/engineering`.

Удалённый адрес: `https://RINIR-XXXXXX/dashboard/engineering`. До загрузки страницы nginx запрашивает отдельный логин и пароль удалённого пользователя.

## Роли

| Роль | Способ входа | Возможности |
|---|---|---|
| Наблюдатель | Удалённый логин и пароль | Просмотр monitoring, history, events и закрытой сервисной страницы |
| Исполнитель | Персональный сервисный код | Изменение объекта и порогов; имя подставляется из реестра |
| Администратор | `ADMIN_ACCESS_CODE` | Настройки объекта, регистрация/удаление исполнителей и удалённых пользователей |

Имя исполнителя невозможно ввести или заменить вручную. В журнал попадает имя, связанное с кодом действующей сессии. Администратор фиксируется как `Администратор`.

## Что находится на странице

Страница построена сверху вниз в том же порядке, в котором её следует проверять. Просмотр диагностических данных доступен без сервисного кода. Изменение полей требует входа исполнителя или администратора, а подготовка Modbus-оборудования и управление пользователями доступны только администратору.

### Заголовок

| Элемент | Что показывает или делает |
|---|---|
| Строка объекта | Название больницы, расположение и ID установки. До первичной настройки вместо объекта показываются соответствующие предупреждения. |
| `← Мониторинг` | Возвращает на основной экран. Настройки не сохраняет. Если на форме есть метка `НЕ СОХРАНЕНО`, перед переходом нужно сначала решить, сохранять ли изменения. |

### Токовые входы WB-MAI6

Карточки `IN1P`…`IN5P` показывают последнее измеренное значение тока непосредственно из базовых регистров WB-MAI6. Это диагностические значения, а не давление в барах.

| Надпись на карточке | Значение |
|---|---|
| Число в `mA` | Последний достоверно прочитанный ток петли. |
| `сигнал в диапазоне` | Ток не ниже `4 mA`; давление рассчитывается линейно в диапазоне `0…10 bar`. |
| `валидный ноль` | Ток от `3.5 mA` до `4 mA`; приложение показывает `0.0 bar`. Это допуск нижней точки, а не обрыв. |
| `обрыв / нет сигнала` | Ток ниже `3.5 mA`; значение давления не используется и канал получает состояние `НЕТ ДАННЫХ`. |
| `не опрашивается / нет данных` | Канал выключен в настройках либо свежего ответа WB-MAI6 нет. Причину определяют по флагу активности и карточке Modbus ниже. |

Показания обновляются после завершения полного последовательного цикла. Все активные газовые каналы одного цикла публикуются одним снимком с одинаковым временем измерения.

### Состояние Modbus, InfluxDB и MAX

| Карточка | Что означает |
|---|---|
| `<газ> / Modbus` | Возраст последнего измерения активного газового канала. Зелёная карточка означает, что значение ещё не устарело; красная — свежих данных нет. |
| `InfluxDB` | Результат записи истории. При нормальной работе показывает `ok` и время последней успешной записи. Ошибка здесь не отменяет текущие показания на экране, но означает, что история может не сохраняться. |
| `MAX` | Состояние отправки уведомлений. `отключён` является штатным, если интеграция выключена. `error` означает, что последняя доставка не удалась после повторов. |

### Доступ к настройкам

| Элемент | Назначение |
|---|---|
| Индикатор `ТОЛЬКО ЧТЕНИЕ` | Поля доступны только для просмотра. |
| Поле `Персональный сервисный код` | Код зарегистрированного исполнителя. |
| Кнопка `Войти` | Открывает сессию исполнителя и связывает последующие изменения с его ФИО. |
| Поле `Администраторский код` | Значение `ADMIN_ACCESS_CODE` из защищённых factory credentials. |
| Кнопка `Управление` | Открывает сессию администратора, включая подготовку оборудования и управление учётными записями. |
| Строка `Сессия` | Показывает ФИО исполнителя либо `Администратор`. Сессия ограничена по времени. |
| Кнопка `Завершить` | Немедленно закрывает сервисную сессию. Несохранённые изменения не записывает. |

### Объект и пороговые зоны

| Поле или индикатор | Назначение |
|---|---|
| `НЕ СОХРАНЕНО` | Форма изменена, но рабочая конфигурация ещё не заменена. Фоновое обновление диагностики черновик не стирает. |
| `ID установки из Debian hostname` | Неизменяемый идентификатор `RINIR-XXXXXX`, полученный из hostname Debian. Через эту страницу не редактируется. |
| `Название больницы` | Название объекта на Dashboard, в событиях и уведомлениях. Обязательная строка до 120 символов. |
| `Расположение` | Помещение или зона установки. Обязательная строка до 120 символов. |
| Флажок `<газ> — INxP` | Включает или исключает физический канал. Должно быть выбрано от трёх до пяти каналов. Неактивный канал не опрашивается, не отображается и не влияет на аварии. |
| Счётчик `<N> активно` | Количество отмеченных газовых каналов. |

Четыре порога задают границы зон отдельно для каждого активного газа:

| Поле | Переход при движении давления в указанную сторону |
|---|---|
| `Красная → жёлтая` | Давление поднялось из нижней аварийной зоны в нижнюю предупредительную. |
| `Жёлтая → зелёная` | Давление поднялось из нижней предупредительной зоны в нормальную. |
| `Зелёная → жёлтая` | Давление поднялось из нормальной зоны в верхнюю предупредительную. |
| `Жёлтая → красная` | Давление поднялось из верхней предупредительной зоны в верхнюю аварийную. |

Названия полей задают границы зон; гистерезис предотвращает частое переключение состояния около границы. Пороговые значения объекта должны быть утверждены ответственным специалистом и проверены при аппаратном FAT.

### Общие параметры

| Поле | Назначение |
|---|---|
| `Максимум шкалы, бар` | Верхняя граница графического отображения давления. Должна быть выше самого высокого аварийного порога. Не меняет электрическую шкалу WB-MAI6 `0…100`. |
| `Гистерезис, бар` | Запас около порога, который должен быть пройден перед обратной сменой состояния. Допустимо `0…1 bar`. |
| `Период полного цикла опроса, мс` | Время между запусками полных последовательных циклов всех активных каналов. Заводское значение `1000 ms`, рекомендуемый диапазон `1000…3000 ms`, допустимый `1000…10000 ms`. Это не задержка между отдельными каналами. |

### Modbus-оборудование

| Поле или кнопка | Назначение |
|---|---|
| `Unit ID WB-MAI6` | Адрес WB-MAI6, который использует штатный опрос. Допустимо `1…247`. Заводской целевой профиль RINIR — `65`. |
| `Unit ID WB-MR3LV/I` | Адрес релейного модуля. Поле активно после отметки `Оборудование установлено`. Заводской целевой профиль — `66`. |
| `Подготовить WB-MAI6` | Выполняет commissioning единственного подключённого WB-MAI6: обнаруживает модуль, назначает сохранённый Unit ID, настраивает `IN1P…IN5P` как `4–20 mA` со шкалой `0…100`, `IN6P` как сухой контакт, переводит связь на `115200 8N2` и проверяет настройки чтением. |
| `Подготовить WB-MR3LV/I` | Обнаруживает единственный подключённый WB-MR3LV/I, назначает сохранённый Unit ID, переводит связь на `115200 8N2` и проверяет её. Не включает автоматическое управление и не переключает K1. |

Обе кнопки являются операциями записи в Modbus-устройство. Это не обычная проверка связи и не кнопки, которые требуется нажимать при каждом запуске. Они предназначены для первичной подготовки нового модуля либо для его замены.

### Аварийное управление клапанами

| Поле | Назначение |
|---|---|
| `Оборудование установлено` | Сообщает приложению, что WB-MR3LV/I и цепь обратной связи физически присутствуют. Само по себе реле не включает. |
| `Режим: Только контроль` | Читает обратную связь `IN6P`, показывает и журналирует её, но не пишет Coil K1. Это первый режим при пусконаладке. |
| `Режим: Автоматическое управление` | Разрешает приложению удерживать K1 при настроенных причинах. Включается только после полного аппаратного FAT. |
| `Задержка срабатывания, с` | Сколько должна непрерывно существовать причина аварии до подачи общего сигнала K1. |
| `Задержка возврата, с` | Сколько должна непрерывно сохраняться нормализация всех причин до снятия K1. |
| `Таймаут обратной связи, с` | Максимальное ожидание совпадения команды K1 с состоянием `IN6P`; превышение формирует неисправность обратной связи. |
| `Срабатывать при потере данных` | Разрешает состоянию `НЕТ ДАННЫХ` быть причиной общего сигнала. Действует только в автоматическом режиме. |
| `Какие аварии подают общий сигнал` | Выбирает активные газы, авария которых участвует в одной общей команде K1. Это не назначение отдельных газов отдельным реле. |

### Сохранение

| Элемент | Назначение |
|---|---|
| `Исполнитель` | Показывает, чьим именем будет записано изменение. |
| `Проверить и сохранить` | Проверяет всю форму как одну конфигурацию и только затем атомарно сохраняет её. Кнопка не выполняет аппаратную диагностику, не программирует WB-модули и не проверяет токовые петли. |
| Строка сообщения | Показывает успешное завершение либо причину отказа. При отказе рабочие настройки не меняются, черновик остаётся на экране. |

### Администрирование доступа

Раздел виден только администратору.

| Элемент | Назначение |
|---|---|
| `ФИО исполнителя` | Имя, которое будет автоматически попадать в журнал изменений. |
| `Персональный код` | Код длиной 8–64 символа для входа исполнителя. После добавления повторно не показывается. |
| `Добавить` в разделе исполнителей | Регистрирует пару ФИО/код. Одинаковые ФИО без учёта регистра и одинаковые коды запрещены. |
| `Удалить` у исполнителя | Удаляет исполнителя и завершает все его активные сервисные сессии. |
| `Логин` | Имя пользователя удалённого HTTPS-доступа: 3–32 символа, латинские буквы, цифры, `.`, `_`, `-`. |
| `Пароль` | Пароль удалённого пользователя длиной 10–128 символов. После добавления повторно не показывается. |
| `Добавить` в разделе удалённых пользователей | Создаёт пользователя в `auth-service`; пароль сохраняется только как `scrypt` hash. |
| `Удалить` у удалённого пользователя | Закрывает этому логину последующую удалённую авторизацию. Последнего пользователя удалить нельзя. |

## Первичная настройка

1. Ввести администраторский код из `/etc/gas-monitoring/factory-credentials.txt`.
2. В разделе «Исполнители» указать ФИО и выдать персональный код длиной 8–64 символа.
3. Передать код только соответствующему исполнителю.
4. Завершить администраторскую сессию.
5. Исполнителю войти по своему коду и убедиться, что ФИО заполнено автоматически.

Персональные коды хранятся в persistent Node-RED context только как HMAC-SHA-256. UI после регистрации код не показывает. При удалении исполнителя его активные сервисные сессии прекращаются.

## Объект и пороги

В действующей сессии заполнить:

- `Название больницы`, например `ГАУЗ "БСМП"`;
- `Расположение`, например `РЕАНИМАЦИЯ, 2 ЭТАЖ`;
- от 3 до 5 активных датчиков по явной карте входов;
- четыре границы каждого газа;
- максимум шкалы и гистерезис.

При установленной опции WB‑MR3LV/I здесь же задаются режим `Только контроль`/`Автоматическое управление`, управляющие аварии, реакция на потерю данных и задержки. Для каждого активного газа флажок содержит обозначение, название и физический вход, например `N₂O — Закись азота — IN4P`. Все пять газов могут быть причиной одного общего сигнала; неактивный датчик не может сформировать команду. Это не настройка пяти отдельных реле. Автоматический режим до аппаратного FAT не включается.

Карта входов фиксирована:

| Флаг в UI | Газ | Вход WB-MAI6 |
|---|---|---|
| `O₂ — IN1P` | Кислород | `IN1P` |
| `AIR — IN2P` | Сжатый воздух | `IN2P` |
| `VAC — IN3P` | Вакуум | `IN3P` |
| `N₂O — IN4P` | Закись азота | `IN4P` |
| `CO₂ — IN5P` | Углекислый газ | `IN5P` |

Неотмеченный канал не опрашивается, не участвует в общем статусе, не вызывает аварию клапанов и не отображается на Dashboard.

Фоновая диагностика обновляется раз в пять секунд, но больше не перезаписывает изменённую форму. Метка `НЕ СОХРАНЕНО` остаётся до успешного нажатия «Проверить и сохранить».

Порядок границ:

```text
0 ≤ красная→жёлтая ≤ жёлтая→зелёная
  < зелёная→жёлтая ≤ жёлтая→красная
  < максимум шкалы
```

Объект, расположение и пороги сохраняются одной транзакцией. При ошибке введённый черновик остаётся в форме, а persistent-настройки не меняются.

## Удалённые пользователи

Администратор регистрирует логин и пароль в сервисном UI. Ограничения:

- логин: 3–32 символа, латинские буквы, цифры, `.`, `_`, `-`;
- пароль: 10–128 символов;
- логины уникальны без учёта регистра;
- удалить последнего пользователя нельзя.

Пароли передаются только по HTTPS, хэшируются `scrypt` во внутреннем `auth-service` и сохраняются в volume `auth-data`. Node-RED не получает и не отображает сохранённые хэши. Начальный пользователь создаётся из factory credentials только при пустом `auth-data`.

## Диагностика без разблокировки

В верхней части страницы отображаются карточки токовых входов `IN1P`…`IN5P` WB-MAI6. Для активных каналов карточка показывает последнее фактическое значение тока в `mA`. Показание считается устаревшим после большего из двух интервалов: трёх полных циклов опроса или `GAS_STALE_TIMEOUT_MS` (`6000 ms` по умолчанию). Неактивные каналы не опрашиваются и отображаются как `не опрашивается / нет данных`.

Для диагностики в редакторе Node-RED узел `WB-MAI6 live current` отправляет в Debug sidebar структурированное сообщение с полями `input`, `currentMa`, `pressureBar`, `status`, `reason` и `updatedAt`. Сообщения формируются только для каналов, участвующих в последовательном цикле опроса.

В разделе общих параметров задаётся период полного цикла опроса датчиков в миллисекундах. Для профиля `115200 8N2` заводское значение — `1000 ms`, рекомендуемый диапазон — `1000…3000 ms`. UI принимает только целые значения `1000…10000 ms`. Ответы активных входов отображаются после завершения всего цикла с единым временем снимка.

## Подготовка заменённого Modbus-оборудования

В режиме администратора раздел `Modbus-оборудование` содержит действия `Подготовить WB-MAI6` и `Подготовить WB-MR3LV/I`. Нажатие открывает подтверждение `Остановить опрос и подготовить …?`. После подтверждения штатный опрос временно прекращается, поэтому значения на Dashboard в течение операции не обновляются.

Перед нажатием:

1. Проверить физическое питание, `A → A`, `B → B` и общий провод RS-485.
2. Оставить на шине ровно один модуль выбранного типа. Второй модуль другого поддерживаемого типа может оставаться, если его адрес не конфликтует.
3. Указать целевые Unit ID. Они должны находиться в диапазоне `1…247` и различаться.
4. Обязательно нажать `Проверить и сохранить`. Кнопка подготовки использует сохранённые Unit ID; несохранённые значения формы в commissioning не передаются.
5. Не запускать параллельно `mbpoll`, Web-конфигуратор Wiren Board или другой Modbus-master.
6. Для WB-MR3LV/I оставить K1 отключённым от исполнительной автоматики до отдельной проверки безопасного состояния.

Последовательность автоматической операции:

1. USR-DR134 переводится на `9600 8N2`, чтобы обнаружить новый WB-модуль с заводским профилем связи.
2. Выполняется последовательное сканирование Unit ID `1…247` и проверяется модель устройства.
3. Для WB-MAI6 записываются типы входов и шкала: `IN1P…IN5P` — `4–20 мА`, `0…100`; `IN6P` — сухой контакт.
4. Выбранному модулю назначается сохранённый целевой Unit ID и профиль `115200 8N2`.
5. USR-DR134 возвращается на `115200 8N2`.
6. Устройство повторно обнаруживается на целевом Unit ID, а записанные параметры читаются обратно.
7. При успехе появляется сообщение `Оборудование подготовлено и проверено`, после чего штатный опрос возобновляется.

Операция может занимать заметное время, потому что сканирует весь диапазон адресов строго последовательно. Не перезагружать ПК, USR-DR134 и WB-модуль до появления результата.

Кнопка `Подготовить WB-MAI6` не проверяет датчик давления, полярность токовой петли, реальные точки `4/12/20 mA` или правильность назначения газа физическому входу. После успешной подготовки необходимо убедиться, что карточки токовых входов обновляются, а затем выполнить аппаратный FAT.

Кнопка `Подготовить WB-MR3LV/I` изменяет только Unit ID и параметры связи. Она не включает флажок `Оборудование установлено`, не выбирает автоматический режим, не переключает K1 и не подтверждает безопасное состояние внешней клапанной автоматики.

Если появляется сообщение `Подготовка оборудования не завершена`, не нажимать кнопку повторно без проверки причины. Проверить питание, A/B, общий провод, отсутствие второго устройства того же типа, конфликт Unit ID и доступность USR-DR134. При ошибке программа пытается вернуть шлюз на рабочий профиль `115200 8N2`; после этого необходимо убедиться, что штатный опрос восстановился. Технические evidence операции сохраняются в persistent-каталоге `/data/commissioning-evidence` внутри Node-RED.
