# Уведомления MAX

Интеграция подготовлена и по умолчанию отключена. Она отправляет сообщение только при переходе состояния канала: `НОРМА`, `ВНИМАНИЕ`, `АВАРИЯ`, `НЕТ ДАННЫХ` и восстановление.

## Настройка

В локальном `.env` или `/etc/gas-monitoring/gas-monitoring.env`:

```dotenv
MAX_NOTIFICATIONS_ENABLED=true
MAX_API_URL=https://platform-api2.max.ru
MAX_BOT_TOKEN=<токен-бота>
MAX_CHAT_ID=<идентификатор-чата>
MAX_REMINDER_INTERVAL_MINUTES=30
MAX_RETRY_COUNT=2
```

Для отправки недостаточно одного токена: API также требует `chat_id` либо `user_id`. В проекте выбран `chat_id`.

Токен передаётся только заголовком `Authorization`, как требует актуальный API. Реальный токен запрещено помещать в Git; в `.env.example` остаётся пустое значение, а production-файл имеет права `0600`.

## Проверка

1. Создать тестовый чат и добавить бота.
2. Заполнить `MAX_BOT_TOKEN` и `MAX_CHAT_ID`.
3. Включить интеграцию.
4. На FAT-профиле последовательно подать `warning`, `alarm`, `normal`, `nodata`.
5. Для каждого перехода должно прийти ровно одно сообщение; продолжающееся ненормальное состояние создаёт напоминание только через `MAX_REMINDER_INTERVAL_MINUTES`.
6. При HTTP-ошибке выполняется `MAX_RETRY_COUNT` повторов с задержкой 5 секунд.
7. Последняя успешная доставка или окончательная ошибка видна на сервисной странице.
8. После проверки заменить или отозвать тестовый токен, если этого требует политика.

## Локальная проверка без токена

FAT-профиль поднимает `max-mock` на `127.0.0.1:18081` и использует только фиктивные credentials:

```powershell
.\scripts\max-fat.ps1 -Clear
.\scripts\max-fat.ps1 -FailNext 2
.\scripts\fat.ps1 -Scenario alarm
Start-Sleep -Seconds 12
.\scripts\max-fat.ps1 -ShowMessages
```

Три сообщения должны быть приняты даже после двух запланированных HTTP 500.

Без токена live-проверка отправки не выполняется, но flow остаётся работоспособным при `MAX_NOTIFICATIONS_ENABLED=false`.

Официальный источник: [MAX API — отправить сообщение](https://dev.max.ru/docs-api/methods/POST/messages).
