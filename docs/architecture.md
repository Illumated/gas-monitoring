# Архитектура

## Назначение

Система получает давление линий O₂, AIR и N₂O, показывает текущее состояние на настенном экране и сохраняет историю. Интерфейс предназначен прежде всего для медицинского персонала и должен явно отличать норму, предупреждение, тревогу и отсутствие данных.

## Целевая аппаратная схема

```text
PT-506 O₂  4–20 mA ─┐
PT-506 AIR 4–20 mA ─┼─> WB-MAI6, Modbus RTU
PT-506 N₂O 4–20 mA ─┘          │
                               v
                   USR-DR134, Modbus TCP
                               │
                               v
                    Node-RED processing
                      │              │
                      v              v
                  Dashboard       InfluxDB
```

Физическое наличие, подключение и текущие настройки оборудования пока не подтверждены runtime-доказательствами.

## Контейнерная схема

```text
Windows 10 / Docker Desktop / WSL2
└── Compose project gas-monitoring
    ├── node-red
    │   ├── image: product-specific pinned build
    │   ├── port: 127.0.0.1:1880
    │   └── volume: node-red-data
    └── influxdb
        ├── image: InfluxDB OSS 2 pinned version
        ├── port: 127.0.0.1:8086
        ├── volume: influxdb-data
        └── volume: influxdb-config
```

Порты публикуются только на loopback. Связь контейнеров выполняется по внутренней сети `backend`.

## Владение конфигурацией

- Git хранит `flows/flows.json`, Docker Compose, настройки без секретов, тесты и документацию.
- Docker image содержит проверенную рабочую версию flow и palette dependencies.
- При старте репозиторный flow разворачивается в persistent Node-RED volume.
- Локальный `.env` содержит только конкретные секреты и не хранится в Git.
- Runtime-изменения через Node-RED editor должны быть экспортированы обратно в репозиторий до следующего развёртывания.

## Требуемая обработка отказов

- Ошибка датчика или специальное значение не преобразуется в давление.
- Потеря Modbus-данных переводит канал в `НЕТ ДАННЫХ` за утверждённый timeout.
- Старое корректное значение не должно бесконечно отображаться как норма.
- Недоступность InfluxDB не должна останавливать текущую индикацию.
- Перезапуск контейнера не должен уничтожать историю, context или credentials.

## Неподтверждённые решения

- клинические пороги каждого газа;
- stale timeout, hysteresis и alarm delay;
- приоритет общего статуса;
- production-схема authentication и network access;
- правила MAX-уведомлений;
- окончательный InfluxDB bucket и retention.
