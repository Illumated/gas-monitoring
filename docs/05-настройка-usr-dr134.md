# 05. Первичная настройка USR‑DR134

Шлюз преобразует запросы Modbus TCP от Node‑RED в Modbus RTU для WB‑MAI6. Настройка выполняется до конфигурирования WB‑MAI6.

## Целевые параметры

| Параметр | Значение проекта |
|---|---|
| Режим Ethernet | Static IPv4 |
| IP / mask | `192.168.50.10 / 255.255.255.0` |
| Gateway / DNS | не задавать в изолированном сегменте |
| Режим работы | Modbus TCP ↔ Modbus RTU, TCP Server |
| TCP port | `502` |
| Serial | `115200 bit/s`, `8 data bits`, `No parity`, `2 stop bits` (`8N2`) |
| WB‑MAI6 address | `65` |

`8N2` соответствует заводским параметрам RS‑485 устройств Wiren Board. Если read-only inventory регистра `112` покажет другое число стоп-битов, сначала устраните расхождение: параметры шлюза и модуля обязаны совпадать.

## Порядок настройки

При штатной установке factory ISO перечисленные ниже действия выполняет `gas-monitoring-hardware-autoconfigure.service`: он обнаруживает также заводской адрес `192.168.0.7`, применяет рабочую сеть и согласованно переключает USR-DR134 и WB-устройства. Ручная процедура сохраняется для аппаратной диагностики и проверки конкретной прошивки шлюза.

1. Не подключать шлюз к больничной LAN. Соединить его только с отдельным сервисным ПК.
2. Определить текущий заводской адрес по маркировке, инструкции конкретной аппаратной ревизии или фирменной утилите. Не считать значение по умолчанию универсальным.
3. Открыть web-интерфейс шлюза. Для USR-DR134 с заводскими настройками логин и пароль — `admin` / `admin`. Сразу после первого входа сменить заводской пароль администратора и сохранить новый пароль только в защищённом реестре объекта; заводские данные не являются production credentials.
4. Оставить serial-порт шлюза на исходной скорости `9600 8N2`. Подключить Ethernet шлюза к `rinir-modbus`, RS‑485 — ко всем WB-устройствам: `A` к `A`, `B` к `B`, общий провод согласно проектной схеме.
5. На `9600 8N2` проверить связь со всеми WB-устройствами и записать значение `1152` в holding register `110` каждого устройства. После записи устройство сразу переходит на `115200 bit/s`, поэтому потеря ответа от уже переключённого Unit ID ожидаема.
6. Только после записи регистра `110` во все WB-устройства открыть web-интерфейс USR‑DR134, установить `115200 8N2`, применить настройку и перезагрузить шлюз.
7. Повторно проверить все Unit ID уже на `115200 8N2`. Если хотя бы одно устройство не отвечает, вернуть USR‑DR134 на `9600 8N2`, определить не переключённый Unit ID и повторить переход.
8. Сохранить снимки всех страниц настроек и зафиксировать модель, серийный номер, аппаратную и программную версии.

Не переключать USR‑DR134 первым и не запускать production runtime между шагами 5 и 7. Запись регистра `110` является commissioning-операцией и выполняется при остановленном `gas-monitoring.service` одним Modbus-master.

Не включайте несколько режимов преобразования или несколько TCP listener одновременно. В штатной цепочке есть один TCP Server на порту `502` и один опрашивающий Modbus-master.

## Проверка с Debian

```bash
ping -c 3 192.168.50.10
nc -vz -w 3 192.168.50.10 502
ip route get 192.168.50.10
```

Маршрут должен идти через `rinir-modbus`, TCP-порт `502` должен открываться. Затем, при включённом WB‑MAI6, прочитать его параметры контейнерным инструментом:

```bash
sudo systemctl stop gas-monitoring.service
sudo install -d -m 0755 /var/lib/rinir-factory/commissioning
sudo docker run --rm --network host \
  --volume /var/lib/rinir-factory/commissioning:/evidence \
  --entrypoint node gas-monitoring-node-red:0.1.0 \
  /usr/src/node-red/tools/hardware-fat.mjs \
  --inventory --host 192.168.50.10 --port 502 --unit 65 \
  --inputs IN1P,IN2P,IN3P --operator "<исполнитель>" \
  --device-serial "<серийный номер>" --evidence /evidence
```

В evidence ожидаются `baudRateDividedBy100=1152`, `parity=0`, `stopBits=2`, `slaveId=65`. После проверки приложение пока не запускать: следующим этапом выполняется [06 — настройка WB‑MAI6](06-настройка-wb-mai6.md).

## Критерий завершения

- `192.168.50.10` доступен только через Modbus LAN;
- `502/tcp` открыт;
- inventory успешно читает WB‑MAI6 с Unit ID `65`;
- фактические `115200 8N2` подтверждены чтением регистров;
- конфигурация и реквизиты шлюза сохранены в защищённом комплекте объекта.

Если TCP доступен, но Modbus не отвечает, не переходить к записи регистров: проверить питание WB‑MAI6, A/B, общий провод, Unit ID и полное совпадение serial-параметров.
