# 01. Развёртывание стенда

Это главный runbook первого развёртывания на пустом устройстве. Он связывает установку ОС, сеть, оборудование, приложение и приёмку в одну процедуру.

## 1. Зафиксировать состав стенда

До начала записать в журнал работ:

- модель и серийный номер ПК, WB‑MAI6, USR‑DR134 и трёх датчиков;
- MAC-адреса двух LAN и их назначение: `management` и `modbus`;
- имя объекта, расположение установки и ответственного инженера;
- адрес шлюза `192.168.50.10`, WB‑MAI6 Unit ID `65`;
- фактическую схему питания, заземления, RS‑485 и токовых петель.

Требования к ПК: `amd64/x86_64`, два физических Ethernet-интерфейса, отдельный внутренний диск, возможность загрузки с USB. Management LAN получает DHCP; Modbus LAN использует `192.168.50.1/24` без gateway.

**СТОП:** заводской ISO стирает первый внутренний несъёмный диск. Отсоедините диски, которые нельзя потерять.

## 2. Подготовить Windows-сборочную машину

Требуются Windows 10/11 x64, Git for Windows, Docker Desktop в режиме Linux containers, минимум `40 GB` свободного места и доступ в Интернет. Репозиторий необходимо получить через `git clone`, не через GitHub `Download ZIP`. Из PowerShell в корне репозитория:

```powershell
docker version
docker info --format '{{.OSType}}/{{.Architecture}}'
```

Ожидается `linux/x86_64` либо `linux/amd64`. Node.js, npm, xorriso, WSL и отдельная Debian-машина для сборки не требуются: инструменты находятся в закреплённом factory builder image. Чистоту репозитория и тесты проверяет сам сборочный скрипт.

## 3. Подготовить объектовый файл на Windows

```powershell
New-Item -ItemType Directory -Path C:\RINIR-secure -Force
Copy-Item .\deploy\debian\factory.env.example C:\RINIR-secure\factory-RINIR.env
notepad.exe C:\RINIR-secure\factory-RINIR.env
```

Обязательно заменить три `replace-with-*` уникальными значениями: `ADMIN_ACCESS_CODE`, `NODE_RED_ADMIN_PASSWORD`, `REMOTE_INITIAL_PASSWORD`. Файл не добавлять в Git и не пересылать в открытом виде. Если автоматическое назначение LAN не совпадает с разводкой, заполнить `MANAGEMENT_INTERFACE` и `MODBUS_INTERFACE`.

**Критерий завершения:** известны реквизиты сервисного администратора, Node‑RED editor и первого удалённого пользователя; роли LAN зафиксированы.

## 4. Собрать автономный ISO на Windows

Скачать официальный Debian DVD-1 и выполнить Windows-сборку по [02 — Заводская установка](02-factory-installation.md#штатная-сборка-rinir-iso-на-windows). PowerShell-скрипт через Docker Desktop соберёт offline bundle, product images и итоговый RINIR ISO; отдельная Debian-машина и ручной WSL не нужны. Перед физическим стендом выполнить одну чистую установку в виртуальной машине с двумя виртуальными LAN.

**СТОП:** не записывать ISO на стенд, если сборочные тесты или установка в чистой VM не прошли.

## 5. Подготовить загрузочную флешку на Windows

В каталоге результата Windows-сборки проверить два файла:

```text
RINIR-13.6.0-amd64.iso
RINIR-13.6.0-amd64.iso.sha256
```

Проверить SHA‑256 и записать ISO на USB объёмом не менее 16 GB по разделу [«Подготовка загрузочной флешки на Windows»](02-factory-installation.md#подготовка-загрузочной-флешки-на-windows). На флешку записывается именно `RINIR-*.iso`, а не исходный Debian DVD. Все данные на выбранной флешке будут уничтожены.

**Критерий завершения:** checksum совпал, программа записи завершила flash и validation без ошибок, сохранены версия программы и снимок успешной проверки.

## 6. Установить устройство

Подключить management LAN, оставить Modbus LAN отключённым и загрузиться с RINIR USB. Через 10 секунд автоматически запускается текстовый Debian Installer: язык, раскладка, пользователь, hostname, сеть, разметка и GRUB не запрашиваются. Установка включает две перезагрузки. После завершения Chromium должен открыть:

```text
http://127.0.0.1:1880/dashboard/monitoring
```

С management-компьютера открыть `https://<DHCP-IP>/` и войти под `REMOTE_USER` / `REMOTE_INITIAL_PASSWORD` из объектового файла. Предупреждение браузера ожидаемо для самоподписанного сертификата.

Для запуска только подключением флешки UEFI должен быть заранее настроен на приоритет USB. В конце установки Debian Installer создаёт `/var/lib/rinir-factory/install.done`; при следующей загрузке USB передаёт управление внутреннему GRUB. Installer повторно проверяет тот же маркер перед разметкой и отказывается очищать готовое устройство.

## 7. Проверить ОС и сеть

Первичная проверка запускается автоматически после второй загрузки. Отчёт сохраняется в `/var/lib/rinir-factory/acceptance/`; успешный прогон создаёт `initial.pass`. Через Salt проверить `systemctl status gas-monitoring-acceptance.service` и получить отчёт. Затем пройти [03 — Сеть](03-network.md). Обязательные результаты:

- hostname соответствует `RINIR-XXXXXX`;
- default route есть только у `rinir-mgmt`;
- `rinir-modbus` имеет `192.168.50.1/24`;
- Node‑RED `1880` и InfluxDB `8086` не опубликованы в LAN;
- приложение запускается даже при недоступном Salt master.

## 8. Подключить и настроить оборудование

Работать строго по порядку:

1. [04 — Подключение](04-wiring.md).
2. [05 — USR‑DR134](05-usr-dr134-commissioning.md): `192.168.50.10:502`, TCP Server, Modbus TCP↔RTU, `9600 8N2`.
3. [06 — WB‑MAI6](06-wb-mai6-commissioning.md): read-only snapshot, затем профиль `gas-monitoring` — IN1P…IN5P 4–20 мА/0…100 и опциональный сухой контакт IN6P.
4. [08 — аппаратный FAT](08-hardware-fat.md): точки 4/12/20 мА, обрыв и длительный прогон.

Во время записи конфигурации и FAT должен работать только один Modbus-master; приложение предварительно остановить.

## 9. Настроить объект и проверить продукт

В сервисном UI заполнить больницу и расположение, зарегистрировать исполнителей и удалённых пользователей, проверить пороги по [07 — Конфигурация](07-configuration.md). Затем выполнить [09 — Проверка выпуска](09-release-verification.md), проверить состояния `НОРМА`, `ВНИМАНИЕ`, `АВАРИЯ`, `НЕТ ДАННЫХ`, историю и журнал событий.

## 10. Завершить приёмку

Создать первый backup по [11 — Backup и restore](11-backup-restore.md). Сохранить вместе:

- acceptance report;
- JSON evidence настройки WB‑MAI6 и аппаратного FAT;
- снимки настроек USR‑DR134;
- заполненный [протокол FAT](28-hardware-fat-protocol.md);
- checksums ISO и приложенных файлов;
- версию Git и перечень серийных номеров.

До подписания этих материалов стенд считается введённым в испытательную, но не клиническую эксплуатацию.
