# 08. Аппаратный FAT WB-MAI6 и USR-DR134

Аппаратный FAT выполняется после настройки входов по [06 — WB‑MAI6](06-wb-mai6-commissioning.md) и до клинической приёмки. Скрипт `scripts/hardware-fat.mjs` работает только на чтение: в нём нет вызовов записи Modbus-регистров.

## Ограничения и подготовка

1. Подключить поверенный источник тока 4–20 мА вместо датчика.
2. Остановить Node-RED и другие Modbus-master, чтобы через USR-DR134 работал только один опрашивающий клиент.
3. Зафиксировать модель, серийный номер, версии прошивок WB-MAI6 и USR-DR134, схему подключения и данные источника тока.
4. Из веб-интерфейса USR-DR134 сохранить снимки настроек `Modbus TCP ↔ Modbus RTU`, TCP-порта и `115200 8N2`. WB-MAI6 за прозрачным шлюзом не содержит идентификационные данные самого USR-DR134, поэтому скрипт не может получить их через Modbus.
5. Утвердить допустимое отклонение в единицах raw. Скрипт требует `--tolerance-raw` и не подставляет инженерный допуск самостоятельно.

Не подключать источник тока к действующей медицинской линии без утверждённой схемы отключения и ответственного за медицинскую газовую систему.

## Переменные командной строки

| Переменная | Назначение |
|---|---|
| `--host` | IP-адрес USR-DR134; по умолчанию `192.168.50.10` |
| `--port` | Modbus TCP port; по умолчанию `502` |
| `--unit` | Modbus address WB-MAI6; по умолчанию `65` |
| `--inputs` | Список входов для inventory или soak, например `IN1P,IN2P,IN3P` |
| `--input` | Один проверяемый вход для точки или обрыва |
| `--operator` | ФИО или идентификатор исполнителя; обязателен для точек и обрыва |
| `--device-serial` | Инвентарный или серийный номер испытуемого модуля |
| `--current-ma` | Фактически установленная точка: только `4`, `12` или `20` мА |
| `--tolerance-raw` | Утверждённое максимальное отклонение от `0`, `80` или `160` |
| `--samples` | Количество чтений точки или обрыва; по умолчанию `10` |
| `--interval-ms` | Пауза между чтениями; по умолчанию `200 ms`, для soak `1000 ms` |
| `--duration-seconds` | Продолжительность soak; обязательна только для `--soak` |
| `--max-gap-ms` | Максимальный допустимый разрыв между чтениями одного входа; обязателен для `--soak` |
| `--evidence` | Каталог JSON-доказательств; по умолчанию `commissioning-evidence` |

## 1. Read-only inventory

```powershell
node scripts/hardware-fat.mjs --inventory `
  --host 192.168.50.10 --port 502 --unit 65 `
  --inputs IN1P,IN2P,IN3P `
  --operator "Иванов И.И." --device-serial "WB-MAI6-..."
```

Inventory читает:

- модель, build, версию прошивки и серийные слова WB-MAI6;
- регистры RS-485 `110…114` и Modbus address `128`;
- тип, нижнюю и верхнюю границы и текущее значение выбранных входов.

Ожидается `baudRateDividedBy100=1152`, `parity=0`, `stopBits=2`, `slaveId=65`. Любое расхождение сначала фиксируется; этот FAT-скрипт его не исправляет.

## 2. Точки 4/12/20 мА

Для каждого из `IN1P`, `IN2P`, `IN3P` физически установить ток, дождаться стабилизации и выполнить три команды:

```powershell
node scripts/hardware-fat.mjs --point --input IN1P --current-ma 4  --tolerance-raw <утверждённый_допуск> --operator "Иванов И.И."
node scripts/hardware-fat.mjs --point --input IN1P --current-ma 12 --tolerance-raw <утверждённый_допуск> --operator "Иванов И.И."
node scripts/hardware-fat.mjs --point --input IN1P --current-ma 20 --tolerance-raw <утверждённый_допуск> --operator "Иванов И.И."
```

Ожидаемые raw-значения: `4 мА → 0`, `12 мА → 80`, `20 мА → 160`. Команда возвращает `PASS`, только если все чтения попали в заданный допуск и не было ошибок обмена.

## 3. Обрыв петли

Физически разомкнуть проверяемую токовую петлю:

```powershell
node scripts/hardware-fat.mjs --break --input IN1P --operator "Иванов И.И."
```

`PASS` означает, что каждое чтение вернуло документированный код отсутствия измерения `32767` или `-32768`. Повторить для всех трёх используемых входов и затем восстановить соединение.

## 4. Длительный Modbus-прогон

После восстановления всех петель оставить стабильный входной сигнал. Первый приёмочный прогон — 24 часа:

```powershell
node scripts/hardware-fat.mjs --soak `
  --inputs IN1P,IN2P,IN3P `
  --duration-seconds 86400 --interval-ms 1000 --max-gap-ms 4000 `
  --operator "Иванов И.И." --device-serial "WB-MAI6-..."
```

Значение `4000 ms` в примере соответствует текущему `GAS_STALE_TIMEOUT_MS`; окончательный критерий должен быть утверждён вместе с эксплуатационными требованиями. `PASS` требует отсутствия ошибок чтения, кодов недостоверного измерения и превышений `--max-gap-ms`. JSON содержит каждое чтение, количество циклов, фактическую длительность, максимальный разрыв, минимум, максимум и среднее по каждому входу.

## Evidence и подписание

Каждый запуск создаёт отдельный JSON в `commissioning-evidence/`. Каталог исключён из Git, потому что содержит объектовые данные. После испытаний:

1. Скопировать JSON, снимки USR-DR134, паспорта и скриншоты HMI в защищённый каталог объекта.
2. Заполнить [28 — протокол FAT](28-hardware-fat-protocol.md).
3. Указать SHA-256 каждого приложенного файла.
4. Подписать протокол исполнителем и представителем принимающей стороны.

Симулятор проверяет только процедуру и формат evidence. Он не заменяет физические точки, обрыв петли или 24-часовой прогон.
