# 22. Modbus и карта регистров

## Целевой профиль

| Параметр | Значение | Статус |
|---|---|---|
| Gateway | `192.168.50.10:502` | Заявлено |
| Transport | Modbus TCP → RTU | Заявлено |
| Slave ID | `65` | Заявлено |
| Serial | `9600 8N2` | Должно быть подтверждено inventory |
| Input type | 4–20 мА, code `4866` | Подтверждено документацией |
| External scale | `0…160` | Проектное решение для 0–16 bar |

## Каналы

Полная карта `IN1P…IN6P` и `IN1N…IN6N`, включая четвёртый канал, приведена в [06 — WB‑MAI6](06-wb-mai6-commissioning.md). Продуктовый flow сейчас использует только:

| Газ | Вход | Type holding u16 | Scale low i16 | Scale high i16 | Value input i16 |
|---|---|---:|---:|---:|---:|
| O₂ | IN1P | 5120 | 5128 | 5130 | 5380 |
| AIR | IN2P | 9216 | 9224 | 9226 | 9476 |
| N₂O | IN3P | 13312 | 13320 | 13322 | 13572 |

`IN4P…IN6P` и все входы `N` не добавляются в dashboard без назначения газа, единиц измерения и порогов.

При шкале `0…160` корректное пересчитанное значение преобразуется как `pressure_bar = raw / 10`.

Регистры границ — отдельные знаковые 16-битные значения. Соседние адреса принадлежат входам `INxN`; это не слова одного `i32`.

Целевой профиль обеих сторон — `9600 8N2`. При пусконаладке регистры WB‑MAI6 `110…113` читаются до любого изменения, а web-настройки USR‑DR134 сохраняются снимками. Любое расхождение устраняется до проверки входов.

## Специальные значения

- `32767` (`0x7FFF`) — подтверждённый код ошибки пересчитанного i16.
- `-32768` может использоваться как защитный фильтр, но не документируется как основной подтверждённый код WB-MAI6.
- Отсутствующее, нечисловое или устаревшее значение должно приводить к `nodata`.

## Расхождения исходного flow

Исходный `flows/flows.json` использует direct serial `/dev/ttyS0`, `9600 8N2`, Unit ID `1`, `HoldingRegister` и деление на `100`. Это состояние сохранено первым коммитом и не считается целевой конфигурацией без отдельного подтверждения владельца.

## Правило изменения оборудования

Перед любой записью:

1. Прочитать текущие значения.
2. Сохранить вывод команды и дату.
3. Записать только согласованный регистр.
4. Прочитать значение обратно.
5. Проверить сохранение после power cycle.

Полная процедура и проверенный скрипт: [06 — WB‑MAI6](06-wb-mai6-commissioning.md).
