# RINIR — мониторинг давления медицинских газов

Система контролирует от трёх до пяти явно выбранных линий: O₂, сжатый воздух, вакуум, N₂O и CO₂. Карта `O₂—IN1P`, `AIR—IN2P`, `VAC—IN3P`, `N₂O—IN4P`, `CO₂—IN5P` и флаги активности задаются в сервисном UI. Сигналы 4–20 мА принимаются через WB‑MAI6 и USR‑DR134; опционально система контролирует общий аварийный режим и управляет удерживаемым контактом WB‑MR3LV/I. Node‑RED Dashboard показывает состояние, InfluxDB хранит историю, MAX получает уведомления.

## Быстрая проверка репозитория

Из корня репозитория:

```bash
npm ci
npm test
npm run audit:flow
npm run audit:secrets
```

На Windows программный FAT запускается так:

```powershell
.\scripts\simulation.ps1 start
.\scripts\simulation.ps1 oxygenalarm
.\scripts\simulation.ps1 status
.\scripts\simulation.ps1 stop
```

## Границы готовности

Программная часть готова к стендовому развёртыванию. До клинической эксплуатации необходимо отдельно утвердить пороги, выполнить обследование объекта, проверить токовые петли и всю Modbus-цепочку, провести аппаратный FAT и подписать приёмочный протокол. Значения порогов в репозитории являются стендовыми.

## Ключевые правила проекта

- Правила разработки, источники истины и обязательные gates описаны в [AGENTS.md](AGENTS.md).
- Единственный рабочий flow — `flows/flows.json`; происхождение исходного импорта описано в [29 — Реестр источников](docs/29-source-register.md).
- Production работает на Debian 13 amd64, в Docker Compose, с локальными persistent volumes и годовым retention.
- Node‑RED и InfluxDB слушают только loopback; удалённый интерфейс публикуется через HTTPS на management LAN.
- Секреты и объектовые данные не добавляются в Git.
- Автоматическое управление клапанами поддерживает аварии всех пяти газов, по умолчанию выключено и включается только после аппаратного FAT цепи WB‑MR3LV/I и обратной связи. Простое описание: [15 — Аварийное управление клапанами](docs/15-valve-control.md).
- Версии ОС, Docker, Salt, образов и npm-зависимостей зафиксированы.
